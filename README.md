# AI Schema Designer

> Natural Language ➔ Interactive ER Diagram ➔ Production SQL (PostgreSQL / MySQL)

An intelligent database design tool where you can describe a data model in plain English, visualize and edit it as an interactive Entity-Relationship (ER) diagram, and export clean, deterministic SQL DDL scripts.

---

## 🌟 Key Features

- **Natural Language Schema Generation:** Propose relational schemas from natural language prompts using AI structured output.
- **Interactive ER Diagram:** Visually inspect, add, rename, or remove tables and columns, and draw relationships with primary and foreign keys.
- **Deterministic SQL Generation:** The AI produces only structured JSON; all SQL DDL (`CREATE TABLE`, constraints, keys) is deterministically generated by verified backend code to eliminate SQL injection risks.
- **Dialect Support:** Export ready-to-run SQL for PostgreSQL and MySQL.
- **Refinement with AI:** Prompt the AI to iterate on an existing schema (e.g., *"add an audit log table with foreign keys"*).
- **User Accounts & Saved Schemas:** Secure authentication (Argon2 + HTTP-only JWT sessions) to save, manage, and reopen database designs.

---

## 🏗️ Architecture

```
Natural Language ──AI──▶ JSON Schema ◀──edits── ER Diagram (React Flow)
                               │
                               ▼
                     Deterministic Generator
                               │
                               ▼
                           Final SQL
```

- **Frontend:** Next.js (App Router), Tailwind CSS, React Flow (`@xyflow/react`), Zustand
- **Backend:** NestJS, TypeScript, Zod, `@google/genai`, Helmet, `@nestjs/throttler`
- **Database & Auth:** PostgreSQL, Prisma ORM, Argon2, HTTP-only cookie JWT

## 🚀 Getting Started

### Prerequisites
- Node.js (v20+ recommended)
- PostgreSQL instance
- Google Gemini API Key

### Installation

1. **Clone the repository:**
   ```bash
   git clone <repository-url>
   cd ai-schema-designer
   ```

2. **Backend Setup:**
   ```bash
   cd backend
   npm install
   cp .env.example .env
   # Configure GEMINI_API_KEY, DATABASE_URL, and JWT_SECRET in .env
   npx prisma migrate dev
   npm run start:dev
   ```

3. **Frontend Setup:**
   ```bash
   cd ../frontend
   npm install
   cp .env.local.example .env.local
   npm run dev
   ```

## 🔒 Security Principles

- **Zero Untrusted SQL:** SQL is generated solely by deterministic code from validated JSON.
- **Safe Identifiers:** All table/column names are validated against strict regex and quoted defensively.
- **HTTP-Only Sessions:** Tokens are never stored in `localStorage`; session cookies are HTTP-only and SameSite protected.
- **Strict Authorization:** All schema access is strictly scoped to the authenticated user ID.

## 📡 API Reference & Core Endpoints

All core schema endpoints work for guests without authentication. All request and response bodies use JSON.
Errors always follow a consistent safe envelope with no stack traces:
```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Description is required"
  }
}
```

### 1. Health Check
```bash
curl -X GET http://localhost:4000/api/health
```
**Response (200 OK):**
```json
{
  "status": "ok"
}
```

### 2. Generate Schema from Natural Language
```bash
curl -X POST http://localhost:4000/api/schema/generate \
  -H "Content-Type: application/json" \
  -d '{
    "description": "Design an e-commerce platform with products, categories, customers, and orders",
    "dialect": "postgresql"
  }'
```
**Response (200 OK):**
```json
{
  "schema": {
    "tables": [
      {
        "id": "t_categories",
        "name": "categories",
        "columns": [
          {
            "id": "c_categories_id",
            "name": "id",
            "type": "INTEGER",
            "primaryKey": true,
            "nullable": false,
            "unique": true,
            "autoIncrement": true
          },
          {
            "id": "c_categories_name",
            "name": "name",
            "type": "VARCHAR",
            "length": 100,
            "primaryKey": false,
            "nullable": false,
            "unique": true
          }
        ]
      }
    ],
    "relationships": []
  }
}
```

### 4. Export Schema to SQL DDL
```bash
curl -X POST http://localhost:4000/api/schema/export \
  -H "Content-Type: application/json" \
  -d '{
    "schema": {
      "tables": [
        {
          "id": "t_users",
          "name": "users",
          "columns": [
            {
              "id": "c_users_id",
              "name": "id",
              "type": "INTEGER",
              "primaryKey": true,
              "nullable": false,
              "unique": true,
              "autoIncrement": true
            }
          ]
        }
      ],
      "relationships": []
    },
    "dialect": "postgresql"
  }'
```
**Response (200 OK):**
```json
{
  "sql": "CREATE TABLE \"users\" (\n  \"id\" SERIAL,\n  CONSTRAINT \"pk_users\" PRIMARY KEY (\"id\")\n);"
}
```
