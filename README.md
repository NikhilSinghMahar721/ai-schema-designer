# AI Schema Designer

> Natural Language ➔ Interactive ER Diagram ➔ Production SQL (PostgreSQL / MySQL)

An intelligent database design tool where you can describe a data model in plain English, visualize and edit it as an interactive Entity-Relationship (ER) diagram, and export clean, deterministic SQL DDL scripts.

---

## 🌟 Key Features

- **Natural Language Schema Generation:** Propose relational schemas from natural language prompts using AI structured output.
- **Interactive ER Diagram:** Visually inspect, add, rename, or remove tables and columns, and draw relationships with primary and foreign keys.
- **Deterministic SQL Generation:** The AI produces only structured JSON; all SQL DDL (`CREATE TABLE`, constraints, keys) is deterministically generated by verified backend code to eliminate SQL injection risks.
- **Dialect Support:** Export ready-to-run SQL for PostgreSQL and MySQL.
- **Refinement with AI:** Prompt the AI to iterate on an existing schema (e.g., *"add an audit log table with foreign keys"*).
- **User Accounts & Saved Schemas:** Secure authentication (Argon2 + HTTP-only JWT sessions) to save, manage, and reopen database designs.

---

## 🏗️ Architecture

```
Natural Language ──AI──▶ JSON Schema ◀──edits── ER Diagram (React Flow)
                               │
                               ▼
                     Deterministic Generator
                               │
                               ▼
                           Final SQL
```

- **Frontend:** Next.js (App Router), Tailwind CSS, React Flow (`@xyflow/react`), Zustand
- **Backend:** NestJS, TypeScript, Zod, `@google/genai`, Helmet, `@nestjs/throttler`
- **Database & Auth:** PostgreSQL, Prisma ORM, Argon2, HTTP-only cookie JWT

## 🚀 Getting Started

### Prerequisites
- Node.js (v20+ recommended)
- PostgreSQL instance
- Google Gemini API Key

### Installation

1. **Clone the repository:**
   ```bash
   git clone <repository-url>
   cd ai-schema-designer
   ```

2. **Backend Setup:**
   ```bash
   cd backend
   npm install
   cp .env.example .env
   # Configure GEMINI_API_KEY, DATABASE_URL, and JWT_SECRET in .env
   npx prisma migrate dev
   npm run start:dev
   ```

3. **Frontend Setup:**
   ```bash
   cd ../frontend
   npm install
   cp .env.local.example .env.local
   npm run dev
   ```

## 🔒 Security Principles

- **Zero Untrusted SQL:** SQL is generated solely by deterministic code from validated JSON.
- **Safe Identifiers:** All table/column names are validated against strict regex and quoted defensively.
- **HTTP-Only Sessions:** Tokens are never stored in `localStorage`; session cookies are HTTP-only and SameSite protected.
- **Strict Authorization:** All schema access is strictly scoped to the authenticated user ID.

### 4. Export Schema to SQL DDL
```bash
curl -X POST http://localhost:4000/api/schema/export \
  -H "Content-Type: application/json" \
  -d '{
    "schema": {
      "tables": [
        {
          "id": "t_users",
          "name": "users",
          "columns": [
            {
              "id": "c_users_id",
              "name": "id",
              "type": "INTEGER",
              "primaryKey": true,
              "nullable": false,
              "unique": true,
              "autoIncrement": true
            }
          ]
        }
      ],
      "relationships": []
```

```json

}
```

## 🔐 Auth & Account Endpoints

Session management uses `httpOnly`, `SameSite=Lax` cookies with pinned `HS256` JWTs. CSRF protection verifies `application/json` content type and matches `Origin` headers.

### 5. Register User
```bash
curl -i -X POST http://localhost:4000/api/auth/register \
  -H "Content-Type: application/json" \
  -H "Origin: http://localhost:3000" \
  -d '{
    "email": "developer@example.com",
    "password": "strongPassword123!"
  }'
```
**Response (201 Created):**
`Set-Cookie: session=<token>; Path=/; HttpOnly; SameSite=Lax`
```json
{
  "user": {
    "id": "e6a21074-b25c-4d37-8ff9-b36c2cf59ea1",
    "email": "developer@example.com"
  }
}
```

```bash
curl -i -X POST http://localhost:4000/api/auth/login \
  -H "Content-Type: application/json" \
```

**Response (200 OK):**

## 💾 Saved Schemas Endpoints

All saved-schema endpoints require an authenticated session cookie. `userId` is strictly resolved server-side from the verified session (IDOR protection). Every operation verifies schema validity and enforces limits (50 schemas per user, 200 KB per schema, names 1–100 chars).

### 10. List Saved Schemas
```bash
curl -X GET http://localhost:4000/api/saved-schemas \
  --cookie "session=<token>"
```
**Response (200 OK):**
```json
{
  "items": [
    {
      "id": "7b3b3a4a-0a78-45b6-9467-1fa75f28fce4",
      "name": "E-Commerce Database",
      "dialect": "postgresql",
      "updatedAt": "2026-10-28T19:40:00.000Z"
    }
  ]
}
```

### 11. Save New Schema
```bash
curl -i -X POST http://localhost:4000/api/saved-schemas \
  -H "Content-Type: application/json" \
  -H "Origin: http://localhost:3000" \
  --cookie "session=<token>" \
  -d '{
    "name": "E-Commerce Database",
    "dialect": "postgresql",
    "schema": {
      "tables": [ ... ],
      "relationships": [ ... ]
    }
  }'
```
**Response (201 Created):**
```json
{
  "item": {
    "id": "7b3b3a4a-0a78-45b6-9467-1fa75f28fce4",
    "name": "E-Commerce Database",
    "dialect": "postgresql",
    "schema": { ... },
    "createdAt": "2026-10-28T19:40:00.000Z",
    "updatedAt": "2026-10-28T19:40:00.000Z"
  }
}
```

### 12. Get Schema by ID
```bash
curl -X GET http://localhost:4000/api/saved-schemas/7b3b3a4a-0a78-45b6-9467-1fa75f28fce4 \
  --cookie "session=<token>"
```
**Response (200 OK or 404 if not found or belongs to another user)**

### 13. Update Saved Schema
```bash
curl -i -X PUT http://localhost:4000/api/saved-schemas/7b3b3a4a-0a78-45b6-9467-1fa75f28fce4 \
  -H "Content-Type: application/json" \
  -H "Origin: http://localhost:3000" \
  --cookie "session=<token>" \
  -d '{
    "name": "Updated E-Commerce Schema"
  }'
```
**Response (200 OK)**

### 14. Delete Saved Schema
```bash
curl -i -X DELETE http://localhost:4000/api/saved-schemas/7b3b3a4a-0a78-45b6-9467-1fa75f28fce4 \
  -H "Origin: http://localhost:3000" \
  --cookie "session=<token>"
```
**Response (204 No Content)**
